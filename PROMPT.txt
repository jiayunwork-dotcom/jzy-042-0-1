摄影测量里最基础的一环，是把三维点按针孔模型投到像素平面、再叠上镜头的径向切向畸变，反过来还要能从两个视角的匹配像点三角化回三维坐标。我要把这套内核做成一个后端服务，让标定和重建的流水线把一批点作为一个作业提交上来、拿回投影结果或三角化结果。它只做针孔投影与 Brown–Conrady 畸变这件事，不是相册管理，不做滤镜特效，也不碰近轴 ABCD 透镜成像。所有交互经 HTTP。

投影模型钉死：先把相机坐标系下的三维点归一化到 x=X/Z、y=Y/Z 的归一化平面，在归一化平面上施加畸变——径向畸变按 (1 + k1·r² + k2·r⁴) 缩放，其中 r² = x²+y²，切向畸变按 Brown–Conrady 的 p1、p2 两项叠加；畸变后的归一化坐标再经内参映射到像素：u = cx + fx·x_d，v = cy + fy·y_d。特别注意径向畸变必须在归一化平面上算，不能拿像素坐标去凑 r，那样量级会差出好几个数量级。要判断投影点是否落在给定图像尺寸之内并如实标出。

这个服务以「作业」为核心组织，而不是一问一答：一次投影作业携带一组内参与畸变系数、外加一批三维点，服务把整批点投影完，返回每个点的像素坐标和是否在像面内，并汇报这批里落在像面外的点数。三角化作业则携带两台相机各自的内参外参、以及一组两视图之间已匹配的像点对，用中点法或 DLT（固定选一种并说明）反解出每对匹配的三维坐标，再把三维点重投影回两个视图、给出重投影误差；作业级别要报告最大与平均重投影误差。绝不允许把两个视图的像素坐标直接平均一下冒充三维点。

这些不变量验收会逐条核对：k1=k2=p1=p2=0 时，畸变前后像素坐标必须逐点相同；把一批点全部沿光轴（Z 方向）向远处平移、但都仍在相机前方，它们的像点应整体向主点 (cx, cy) 收缩；只把 fx、fy 同时加倍，各像点到主点的半径随之加倍；对一个已知立方体角点做投影再对匹配点三角化，三角化出的三维点重投影回去必须贴回原像素、误差小于给定阈值。方向性不能因为把 X/Z 写成 Z/X、或漏了归一化就整个错掉。

非法输入在开算前拦下，返回带类型的结构化错误：任一点的 Z 小于等于零（点落在相机后方无法投影）、焦距为非正、图像宽或高为零、内参缺项、三角化作业里两台相机外参缺了一台、匹配点对数量为零——逐一拒绝，不抛未捕获异常也不返回空结果。作业里个别点非法（如某点 Z≤0）时，按请求约定要么整作业拒绝、要么标出该点为无效并继续其余点，二者取其一但要一致、可预期。单点投影与批量作业必须共用同一套投影函数，同一个点在两个入口结果要一致。再提供一个回显当前已注册内参预设的只读接口和运行状态接口。随服务预置一个已知立方体角点的标定算例，其投影应全部落在像面内，便于人工核对。

用 Java 17 配 Spring Boot 实现。把针孔投影、Brown–Conrady 畸变、三角化反解与重投影、输入校验、作业编排、HTTP 路由各自拆成独立的类或包，避免把全部逻辑堆进一个巨型文件。用 Docker 一键构建并启动，基于 maven:3.9-eclipse-temurin-17 构建、以 JDK 17 运行。自动化测试要盯：零畸变系数下畸变前后像素一致、点沿光轴远移像点向主点收缩、焦距同时加倍半径加倍、立方体角点三角化重投影贴回原像素、Z≤0 与焦距非正与外参缺帧分别被拒、单点与批量作业同点结果一致、并发多作业互不串扰。
